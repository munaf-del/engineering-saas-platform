# Agent Lanes

Prefer one implementation lane per PR, with optional support from `ui-qa` or `pr-review`. The goal is parallel progress without cross-lane drift.

## Recommended Parallel Patterns

- Safe pair: `core-platform` + `ui-qa`
- Usually safe: `web-ui` + `api-tenancy` when the API contract is unchanged
- Usually safe: `report-author` + `ui-qa` when QA only adds coverage or verifies print/export behavior
- Caution: `domain-sources` + `calc-guard` only when the task explicitly says a rule-pack or standards contract must change
- Avoid in one PR: `api-tenancy` + `calc-guard`
- Avoid in one PR: `calc-guard` + `report-author`
- Avoid in one PR: any implementation lane + `apps/api/prisma/**` unless the task is explicitly schema-focused

## Required Review Gates

- Tenancy gate:
  - required for `apps/api/src/common/tenant/**`, `apps/api/src/common/prisma/**`, auth, organisations, projects, documents, or AI-document ownership changes
- Calc gate:
  - required for `packages/shared/src/types/calculations.ts`, calc DTOs, snapshot hashing, Python models, dispatcher changes, or golden fixture updates
- Reporting gate:
  - required for report evidence bundles, template version binding, annexure snapshots, print/export flows, or spatial sheet provenance
- Source/provenance gate:
  - required for standards metadata, imports, waste-classification source URLs, or any rule-pack and catalogue workflow changes

## Lane Selection Heuristics

- If the task changes how data is isolated between organisations or projects, choose `api-tenancy`
- If the task changes a calc input, result, hash, unit, or supported calc type, choose `calc-guard`
- If the task changes a report, annexure, print route, or template snapshot, choose `report-author`
- If the task changes standards/imports/catalogues or source-backed regulatory content, choose `domain-sources`
- If the task is repo operations, docs, automations, or CI guidance, choose `core-platform`
